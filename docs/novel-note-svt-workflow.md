# 逐章 Note 与 SVT 改编流程

## 业务主线

导入小说 → 核对章节目录 → 一章一 Note → 选范围精读 → 跨章事件 SVT → 人工组合 Note / 选择 SVT → 集 → 场 → 镜 → 确认资产图 → 视频。

原著章节、主线事件、改编集是三个不同对象。禁止按字数把原文切成若干“集”后，将这些阅读单位直接当作拍摄集。

- 同一卷同章的上、中、下合为一个章节，内部保留小节标题及原文区间。不同卷的同号章节不能合并。序章、尾声保留为独立叙事章节；书名、卷名、版权、目录不计章。
- 原始 Note 与章节一一对应。人工合并创建 Note 组合，不删除或重写原始 Note，因此合并后仍能追溯每章原文。
- SVT 是主线关键事件，可引用多个 Note，也允许一个 Note 参与多个 SVT。SVT 不是原文分段，不等于一集，不以时间长度判断是否成立。
- AI 可以建议保留、压缩、合并及理由，但模型任务没有执行 Note 合并的权限。人工可选择不采纳，也可自行组合。

## 第一次精读即可提取的内容

创建 Note 时先确定章节边界和稳定身份，不收费、不声称已读。首次精读同时提取：章节概况、场景、人物、道具、人物变化、事件线索和关键对白。它们来自同一轮阅读，避免为资产和人物变化重复读取整章。

超长章按有限上下文分块，每块输出先验结构与原文引用再落盘。抽取容量不足或输出截断时继续细分，保留已完成分块。Note 的完整状态只在所有块成功后成立。后续“精读补充”复用缓存，只补未读块，或由用户显式要求以新规则重读。

跨章归纳消费有证据的事件与状态变化，不重新把整部小说塞进模型。人物年龄、形态、伤势和社会环境分别记录，附上揭示位置及适用时间；后文状态不得覆盖早期状态。未知身份、指代与矛盾保留为疑点。

## SVT

按选定 Note 范围逐批聚合事件，记录事件来源与引用。每个 SVT 包含：核心冲突、起因与目标、关键行动、结果或未闭合状态、涉及 Note、资产、爆点、爽点、关键对白及其证据。没有爽点或对白就为空，不为凑字段编造。爆点强调情节强度与局势转折，爽点强调前期压力与后续兑现的落差，两者分开。

新一批可延续已有事件，但不得覆盖已完成人工改编的组合。对不确定的同一事件关系仅给建议。精读范围之外的知识不能进入 SVT 的事实或对白。

## 存储及失效

使用独立 `lib/novel_workflow` 模块与项目内 `novel_workflow/` 目录；原文继续由 ArcReel 统一管理。章节身份、阅读分块、原子事实、SVT、人工组合分开保存，源文与各步骤规则的版本分别计算依赖。

原文变化后保留旧产物但标记过期；在途生成提交前再次核对源文与规则。人工合并和生成中途提交不能互相覆盖。阅读和 SVT 各有项目独立规则，执行时冻结版本；编号规则待核对后接入。

长任务复用持久化任务队列、可见进度、停止与续跑。服务重启不以缓存“看起来存在”为由自动继续收费任务。既有暂停仍有效。

## 界面

采用 ArcReel 的布局和基础组件，业务导航按“章节 Note / SVT 事件 / 人工编排 / 集场镜制作”组织。Note 列表显示原著章节标题、阅读状态、人物／场景／道具数量和疑点；详情能展开原文证据。合并操作先显示选中 Note 和来源，再由人工提交。

原生按窗口直接分集保留为可关闭新流程后的独立能力，不作为小说改编的默认前置。启用新流程时，选章、理解和事件提炼先于分集。

## 待核对的编号规范

用户要求遵循 study-main 的 SCN、SEG 编号规则。本机保存的 study-main 原始 SKILL 尚未找到该定义，已请求具体文件。拿到规则前不把 SCN、SEG 臆解为场、镜，也不承诺与原规范一致。内部身份与展示编号分离，待核对后实现统一编号器并接入集、场、镜和资产引用。

## 代码落实与当前边界

已实现独立章节解析、Note 分块抽取、过去证据检索、SVT 有限批次聚合、人工组合及组合到原生集的编排。开关位于项目设置，新建项目默认开启；既有项目可显式开启。Note 原始记录不随人工组合改变；更新已有组合对应集复用同一集身份，不制造重复集。

生产输入清除未按本集范围筛选的全书梗概、下一集大纲及全局资产描述，绑定所选 Note 的原文和阅读版本。Note 生产检查目前验证依据新鲜度与输出结构，并通过提示词约束事实范围；它不是“模型语义完全正确”的保证，不应与原有全书事实审查混称。

原文分块内的证据必须逐字出现且唯一，关键对白还必须属于对应 SVT 的来源事件。不同范围单独提炼时，保留范围外已有 SVT；跨越重做范围的旧 SVT 标记待核对。SVT 的全局语义归并由有限检索辅助，远距离关联仍可能遗漏，不能声称一次自动提炼已解决所有长篇主线归一。

编号待核对范围：GitHub 最新 `study-main.zip`、先前提供的 `ai-novel-deconstruct` Markdown 与 `workbench.json` 均未发现 SCN/SEG/SVT 定义。集、场、镜暂保留原生编号；并未以猜测规则替换。待提供准确 SKILL 后集中实现，业务身份不依赖展示编号。

## 拆书经验补齐（2026-11-09）

逐章精读现在分为证据抽取与整章归纳。抽取沿用有界原文块，新增有证据的别名、带方向的关系、伏笔埋设与回收、章节看点和可观察名场面。看点涵盖爽点、成长、恐惧、伦理冲突、身份揭示、虐点与钩子。整章归纳使用独立 `chapter.md`，分层汇总成一份起因、冲突、行动、结果及钩子，原始记录不被摘要替代。

项目台账由有效 Note 派生，保留身份范围、别名依据、出场章节、状态轨迹、关系变化以及伏笔到回收的引用。回收引用必须来自实际送入模型的早期伏笔；未能对应的回收单列疑点。生成时按揭示位置截断记忆，界面上的累计台账明确提示可能包含后文。别名归一采用同指证据和身份范围，仍不能把字面引用验证等同于语义证明；模糊指代需要保留疑点。

后补前文会改变阅读依赖：后章若依赖旧记忆，标记需更新；重读复用适用的分块缓存，旧结果存入历史。原文、抽取规则、归纳规则与前文阅读版本共同决定有效性。规则仍为项目独立文件，可以分别替换。

SVT 生成读取此前任务的有效 SVT，并限制在所选范围的最晚揭示位置之前。同一事件续接沿用身份；已归类事件不能另建重复 SVT。尚未触达的 SVT 保留，后文 SVT 不进入早期任务提示词。爽点兑现与伏笔回收使用不同字段与界面。

范围收敛使用独立 `review.md`：分批分析所有选中 Note，再分层生成范围总览。保留每批分析和具体建议，每条建议列出必保、压缩、组合或候选省略，附人物弧光、伏笔、关键对白影响及必须保留内容。每个涉及的 Note 都必须有对应证据。选择来源只选中 Note，不执行合并、删除或生产内容更新。原文或阅读依据改变后，建议标记失效。

工程检查能验证引用存在、范围边界、对象引用和人工权限，不能保证模型语义归纳无遗漏。有限检索仍可能漏掉远距离关联；原始事实、分批建议和疑点因此保留供复核。此次部署只升级流程与规则，不自动恢复已暂停的整书精读。

## 跨章理解与回读（2026-11-09）

理解层默认开启，可在“阅读设置”单独关闭。精读完成后自动执行，已精读 Note 也可单独运行。它不改变 Note 的原始事实与章内视角，也不执行章节合并。

检索索引覆盖已登记的全部原文，包括未精读章节。以有证据的 Note 记录为锚点，模型先提出问题及同义表达、称谓、物件或动作检索词，再用本地词项检索获取原文窗口；回读后可提出下一轮搜索词，最多三轮。保留前轮的少量上下文，所有查询、命中章节与回读位置落盘。这里是“模型生成查询 + 本地词项检索 + 模型回读”，不是向量数据库，也不能保证找全所有语义相关段落。

每条关联至少引用两个 Note 的逐字原文，并且至少涉及当前锚点 Note。类型包含身份同指、伏笔回收、状态、世界环境、因果和待核对矛盾。故事适用时间单独记录；读者揭示位置由服务器取所引用证据中最晚的位置，不能让模型把后文真相倒填到前章。证据可核验仅证明引用存在，语义结论仍可能有误。

关联和回查报告保存到 `novel_workflow/understanding/`；项目独立规则为 `rules/understand.md`。原文、规则或 Note 依据改变会使报告失效。中断后的查询与回读结果可复用。界面明确显示可检索章节数、实际回读章节、未完整精读章节及未解决问题，不把检索全书等同于读完全书。

启用理解层时，SVT、范围收敛和编排生产集之前要求选中 Note 完成一次有效回查。未知线索仍作为疑点保存，不以自动推测填满。生产生成只注入本集第一章开始前已揭示且有证据的相关关联；本集内部揭晓仍以本集原文为准。这是保守边界，会舍弃部分虽属于早期事实但尚未揭晓的资料，以免身份、关系或伏笔提前泄露。生产绑定保存过滤后理解资料的版本，生成期间变化会阻止旧依据继续提交。

Note 摘要默认上限提高到 1200 字，可配置 400～3000 字。程序校验上限，超限让模型重新归纳，不做静默截断；短章不强迫凑字数。设置改变使旧摘要需要更新，但仍复用适用的原文抽取缓存。全部事实、引用和分块资料仍独立保存，摘要不是唯一记忆来源。
