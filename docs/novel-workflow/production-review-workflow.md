# 场镜、导演组集与制作交付

## 工作边界

场镜库是候选素材。程序负责结构、引用、版本和已声明状态的检查；AI 提供局部修订与选镜叙事建议；导演/编剧对表演、节奏、取舍、悬念和连续性负责。组集仅提供叙事与制作参考，标注时长不绑定实际视频时长；可选确认绑定当前内容与选镜顺序，修改后重新核对，不要求工作人员泛读全文。

## 操作顺序

1. 在场镜卡片编辑镜头方案：动作、对白、发声方式、时长、出镜与道具引用、起止画面、资产状态。单个 SH 超过 15 秒用 SEG 延续；实际要剪辑时拆成不同 SH。原文对白与改编对白分别标记，改编须附原文依据。保留历史版本。
2. 程序列出必须修复的错误和需要编导判断的提示；允许 AI 生成单镜草稿，展示前后差异后采用，不自动覆盖。
3. 导演选择并排序镜头，预览实际可见、可听的内容。可选运行 AI 叙事检查；人工也可直接审阅所选分镜，不把未选小说信息当成观众已知。
4. 编导可选记录故事、节奏和连续性核对及处理决定。人工确认不作为组集或视频生成的自动关卡；原生剧本的数据结构与资产引用仍须有效。
5. 保存人工选镜的参考编排。导出主线事件、爆点、场景目的、有序对白、资产、原文依据及待定事项；资料不全也可导出参考包。图片核对状态单独记录，不宣称已经保证视频可生成。

## 数据与模块

发声方式区分画内对白、角色画外音、内心独白、叙述旁白；发声角色与出镜资产独立。隐匿和画外对象不自动进入参考图演员列表。原生模型配音的指令与台词一起交付。

镜头编辑、自动检查、AI 建议、编导确认、交付包分别实现，沿用项目规则覆盖与持久任务队列。保留场镜源 ID；拆镜新增 ID，显示编号按原文和当前顺序计算。既有正式剧集不会因修改候选镜头被静默覆盖。

## 组集的业务定位

组集是人工选择场、镜后的叙事参考，不是锁定实际视频生成时长的执行合同。场镜时长与合计时长均作为参考；编导可在后续制作中调整对白、节奏与镜头。工作台不新增语速预算、自动台词时长门槛或强制实测秒数。

人工核对属于可选的内容补充与版本记录，不作为保存参考编排或进入视频生成的自动关卡。原生剧本要求的说话人、有效资产引用与结构约束仍保留，以避免保存无法读取的数据。

参考包优先交付有效信息：选镜顺序、场景时空与目的、来源 Note 和主线事件、爆点场面与关键对白、逐镜动作与有序发声、资产及参考图、起止状态、原文依据、待补事项和人工备注。缺资料也能导出参考包；已核对的资料可另带核对记录，不把候选素材的齐全程度等同于最终视频质量。

## 未明确说话人与检查反馈

参考组集不因说话人尚未确定而阻断。点击创建分集时，尚未归属的对白登记为带资产编号的待定说话角色，保存来源 Note、镜头和对白，并标记身份待确认。占位登记不等于人工确认人物身份，不自动把该角色加入出镜列表，也不要求提前生成人物图片。后续可改绑说话人或使用资产合并统一身份。单纯打开预览不会批量创建待定资产。

AI 观众理解检查在入口旁显示排队、执行、成功和失败，成功后自动载入结果，重新打开可恢复任务状态。跨镜头比较与“缺少过渡”等说明属于 AI 判断，不要求整段说明等同于单句逐字引文；每条建议另附程序取出的实际镜头材料供人工核对。不会自动采用建议或替编导签字。

## 场镜层级与原文对照

SCN 使用独立场标题区，显示编号、地点、时段、叙事目的和镜头数；SH 使用场内镜头卡片。镜头内的主线与爆点、资产、镜头设计、画面与有序台词、来源依据分别分组。

集内的「对应小说原文」用于追溯出处，可以同时包含原著对白和叙述，不能直接等同于整段配音。真正发声以有序台词/发声内容为准。只读界面会压缩 EPUB 缩进和过多空行，但不会改变导入文件、存储的原文摘录或定位索引；原著自身的重复表达和措辞差异仍保留。

## 章节阅读与累计台账

章节详情采用「Note信息」「章节原文」「章节精简稿」三个横向页签。章节标题下同一行显示字数、生成状态与可展开的原著小节。没有 SVT 备选时不显示空备选区。原文与已有精简稿在切换页签后读取，Note 信息内不再重复展示精编稿入口、说明或字数对比；未生成的精简稿仍可由工作人员主动生成。

人物与伏笔台账内再分「人物」「伏笔与回收」两个页签。人物以自适应多列卡片展示；身份依据、人物变化、关系和来源 Note 操作保留，长记录可展开。伏笔、已关联回收和待归属回收在另一页签内展示，空状态分别提示。

## 本次选择与全项目可用范围

左侧勾选、起止章节只选择本次要处理的 Note；泛读与跨章回查按钮位于同一操作行。单选一个已生成 Note 也可运行理解层：该章作为锚点，按人物、线索与问题在可用范围内检索原文片段，可涉及尚未生成 Note 的章节。回查产生关联、证据、检索轨迹和待定问题，不自动为其他章生成 Note，不代表逐章精读全文。只有一章可用时无法据此确认跨章关联，仍保留待查问题。

可用范围是全项目 AI 检索与制作的边界，不是“有哪些 Note 文件”。泛读自动追加所选章；手动加入范围不会创建 Note。默认范围操作为追加，保留原有范围；缩小范围先预览影响并明确确认，同时保存范围变更历史。

已有 Note、SVT 归属及精简稿可在范围外继续浏览。制作与检索仍使用范围内有效资料；展示历史阅读内容不会使它自动获得生产资格。调整范围不删除阅读文件，不重新调用模型。小说项目的分集统一从左侧列表进入，移除顶部重复分集列表入口。


## 小说理解规则与证据约束（2026-11-12）

新模型输出必须显式填写 `claim_type`、`perspective`、`source_kind`；`unverified` 或 `unknown` 还必须填写具体的 `uncertainty_reason`。旧材料允许只读浏览，但缺字段不表示已确认事实。跨章关联只有正文事实结论可标记为受支持，并自动用于生产约束。未判定的身份不自动合并或登记为已确认视觉设定。

Note 分块保留原文前后窗口帮助承接，窗口不承担本块的抽取归属或引文来源。初次抽取后执行 `read_review` 原文审核，再生成整章概况和累计记忆；审核失败可从已保存抽取草稿续接，不重复已完成的抽取调用。该审核仍由模型完成，不保证消除全部语义错误，真实疑点保留供工作人员回查。

跨章回读后，按关联类型和章节组合分批执行 `understand_reconcile`，检查重复和冲突；未核实关联不升级为事实。原始关联及回读证据继续落盘。单次有限检索不是全书覆盖证明，关键词未命中不能判定线索不存在。

SVT 首批决策先接收整章概况、完整事件的有界索引和截至本章的已核实关联，再处理局部事件。一个 Note 仍只有一个正式主归属；辅助、梦境或未判定事件也保留在该归属中，但管理归属不表示它们属于同一现实因果链。场面与原文台词、来源 Note 的既定爆点规则不变。

制作约束可使用当前原文块开始前已经揭示的同章关联；不把之后揭示的信息提前用于早期镜头。这仍是片段级边界，人物各自的认知时间尚需编导对照原文判断。画外发声、内心独白的说话人与出镜人物分别校验，不能因角色发声强迫其入画。受保护引句在精简稿中被改写或丢失时，保留对应原文单元。

每个阶段的有效规则由项目可替换规则、通用事实规则和输出约束版本组成，参与生成缓存及产物版本指纹。“规则与提示词”页面展示有效组合；新项目为每个阶段建立独立规则副本。更新规则不删除旧产物，也不自动付费重跑；旧 Note 和精简稿仍可浏览，生产使用符合当前规则的版本。

长章实跑补充：对白 `quote` 仍只保存原话；同一句短对白在原文块中重复时，用可选 `context_quote` 提供包含本次发言及前后叙述的唯一连续定位窗口，系统据此计算真实原文坐标，不凭最近位置猜说话人。长块的抽取与审核输出额度随块大小调整，并保留自动拆小和断点缓存，避免把输出截断误当作小说信息不足。

引用定位覆盖普通记录与嵌套对白；当模型提供的上下文仍不能唯一定位时，`quote_locations` 从真实原文构造候选窗口，由一个有界模型请求选择位置。选择只能引用给定候选，无法确定必须返回待核实，不按最近距离猜测。结构有效的抽取先缓存为候选，引用定位和原文审核完成后才成为正式片段。

跨章查询规划使用精简索引：保留全部记录、嵌套对白和信息性质，只移除重复引文坐标、定位上下文和空字段；单批索引上限为 14,000 字符。原始证据仍用于回读锚点，不以索引代替原文。兼容来源、阅读规则及范围完全相同的已完成回读缓存，不跳过尚未检查的新分组。

跨章引用若将转述或删去读者插话后的文本误当原文，由独立 `understand_citations` 规则在当前片段的连续原文候选中选择引用。模型只返回候选 ID，服务器恢复原文，不改动关联结论或确定程度；候选不足的关联保留为待核对问题，完整草稿和本轮原文单独落盘，不进入已证实关联；其他通过校验的关联继续保存。片段编号写错时，只有引句在本轮实际原文中有唯一坐标才恢复编号。修复后继续校验原文坐标、跨章依据和信息性质。允许恢复多出的一个句末重复句号，但不容忍改词、内部标点替换或拼接原文。

精读回查与 SVT 提炼保持独立操作。回查完成后，由工作人员明确触发 SVT；自动化验收脚本也只在回查和来源检查成功后单独提交 SVT 任务，不因回查完成而隐式启动其他制作阶段。
