# Note 资产登记与编号

每章精读结果落盘后，把有原文证据的人物、场景和道具登记到 ArcReel 原生项目资产；历史有效缓存也在精读任务收尾同步。无需第二次调用模型。过期阅读结果不参与登记。

- 人物 CHR、场景 LOC、道具 PRP；项目内各自递增，删除不回收号码。
- asset_id 标识制作资产，entity_id 标识人物本体；人物衍生形态独立编号，共享 entity_id。
- 身份键由类型、名字、identity_scope 构成；未限定身份的常见泛称按 Note 分开。不会自动用别名或跨章身份结论强行合并。身份不确定时由创作者使用原生资产合并操作确认。
- Note 中的记录 ID 仍标识证据；project.json 的 note_asset_links 将证据记录关联到稳定资产 ID。阅读文本不因登记被改写。
- 后续原文明确提供 variant 时，登记到原生 derivatives。年龄、变身、伤势须有本段证据；普通情绪变化不需要外观衍生。已有精读缓存不会被追溯推断形态。
- 原生改名保留 ID 和编号；人工合并迁移 Note 引用。并为新衍生时保留原制作资产编号；并入已有资产时使用保留方编号，旧号不复用。删除不因重读被自动复活。
- Note 名称显示编号，可点击进入对应资产页，悬停查看本章描述和原文依据。资产库与 @ 候选显示同一编号；@ 可以按编号搜索，插入仍为原生 `@[人物/形态]`，保持生成链兼容。

生产提示词只使用选定 Note 的原文和允许范围内的理解结果，不注入全局资产的后文描述。资产库是面向创作者的全局资料视图，不等同于某一集允许揭示的剧情。

当前只对相同名字和身份范围自动复用。名字/范围由模型写法不一致时可能产生独立条目，应使用原生合并确认；没有启用模糊匹配去猜测身份。编号代表登记，不代表图片已审核或资产已经可用于成片。

## 首次出现于哪个 Note

人物、场景、道具及人物衍生形态的 `first_note` 保存 Note ID、原文章节顺序和章节标题。按当前有效、已生成 Notes 的顺序取最早出现位置，不按资产登记或任务完成时间排序；尚未阅读的章节不作推断。后来补读更早章节时重新计算，本体与衍生形态分别保留首次位置。人工合并保留更早的来源。

资产卡片、详情及衍生行显示“首次出现：Note 001 · 章节标题”，可点击返回指定 Note。悬停可看完整标题及范围说明。没有 Note 依据的手工资产不伪造来源。

资产编号表示登记身份，首次 Note 表示原文位置，两者顺序可能不同。首次位置也不等同于形态适用区间或读者得知真实身份的位置，不能代替状态时间线与揭示边界。

## 身份、视觉变体与表现状态

同一对象的别称、描述补充和身份范围变化不应反复建本体。抽取时可用 `same_entity_as` 引用输入滚动记忆中的既有资产记录；原文没有同指依据时保留独立对象和身份疑点，不依靠相似名字合并。人工确认入口为资产卡片菜单“并入…”；待确认的 Note 资产也可就地选择本体并保存。

`variant_kind` 区分视觉变体、表现和无变体。年龄、变身、服装与持续伤势可成为独立视觉资产；愤怒、疲劳、笑声、持剑、寒冷感等只记表现或道具关系。固定外观的补充特征沿用本体，例如大型犬与红毛不代表两种形态。场景损坏、道具发光等记入 `state`，随镜头制作信息进入原生制作脚本，不套用人物衍生结构。

`appearance_context` 区分现实、回忆、幻象和梦境。表现记录继承当时的视觉状态；回忆、幻象和梦境中的造型不覆盖现实时间线。明确选择“无变体”可回到本体外观。身份归一不意味着把后期造型或真实身份提前用于早期剧情。

原生合并和本体改名同时迁移 Note 关联、未组集场镜的结构化资产引用及对白说话人，去重引用列表，保留 SCN/SH 编号、对白原文和镜头设计。预览计入场镜引用数量；执行前归档场镜快照，项目与场镜在同一写入事务提交。只对原本有效且仅引用变化的制作依赖更新依据，原有过期内容不会被标为有效。

类型模板、具体个体、组合参考需要分别理解。种类信息不额外生成一个同场人物；同类妖魔模板不代表每次出现都是同一个体；组合参考中的组件复用已有资产，不重复创建实物。身份仍有争议时保留候选与原文理由，不把人物猜测升级为事实。

## 对白归属与原文定位

场镜中的“查看该镜头原文”和待确认对白下的“查看这句对白原文”打开当前生成片段，浅色标出镜头引用范围，深色标出对白，并滚动到匹配位置。弹窗可按显示编号切换镜头。逐字匹配先使用镜头引用范围；只在片段中找到多处同句时保留多处高亮，不假装已经唯一定位。找不到对白原句时提示核对镜头依据与前后文。原文位置使用 Unicode 码点，前端转换后切分，避免特殊字符导致偏移。

生成场镜时模型会尝试填写说话人；语义复核发现的问题可进入待确认列表。单镜的“AI 补判本镜说话人”通过持久任务队列，仅发送当前原文片段、本镜与相邻镜头、当前片段及此前已登记的候选人物称谓，不重跑整章或改写对白。模型须逐条给出候选人物、连续原文依据和理由；无法确定或缺少对应人物资产时保持未确认。补判规则见 `lib/novel_workflow/rules/speaker_attribution.md`，支持项目规则覆盖，并在工作台规则页展示。

补判结果单独保存为建议，不自动修改说话人，也不使镜头制作设计过期。工作人员点击“采用”后通过现有版本校验的对白确认接口填写归属，历史记录保留所采纳的建议与原文依据。既有疑点仍需按界面确认处理结论，补判不自动宣告其他结构或语义问题已经解决。
