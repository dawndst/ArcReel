# 《十二国记》前四章真实验收

验收范围：`月之影·影之海`第一至第四章。每章的上、中、下合成一个 Note，共 106,980 个字符（含导入排版空白），不读取第五章以后的内容。运行项目为 `twelve-kingdoms`。

验收链路：指定章节 → 泛读生成 Notes → 自动跨章精读回查 → SVT 与爆点 → 场镜素材库 → 选择镜头进行组集验证。图片与视频生成不属于本次验收。

## 已发现并修复的阻塞

### EPUB 排版空白导致引文误报

导入文本保留多重换行与不换行空格。模型引用相邻两句时省略这些空白，旧校验要求完全相同，导致反复修正。引用定位现在容忍空白差异，以及给逐字摘录补上的外层引号，最终保存原文真实位置与原始引文。不替换正文中的字词、标点，不容忍省略中间正文或拼接；归一化后有多个匹配仍拒绝。

章节抽取、跨章回查、镜头原文依据复用同一个定位函数。已有精确引用的缓存继续有效。

### 更换主归属后未复核仍可生成场镜

人工采用备选 SVT 后，受影响 SVT 的 `breakdown_status` 为 `needs_review`。场镜生成现在拒绝该状态，并引导选择相关来源 Notes 重新提炼。已生成候选的有效性检查也拒绝待复核归属。

`needs_details` 与 `needs_review` 分开处理：前者表示尚无足够完整爆点，可以生成场镜候选，但界面明确其不代表爆点完整；后者表示归属变化后梗概与爆点尚未复核，必须先重新提炼。不能为了满足爆点数量制造台词。

### 摘要误拒绝输入中已有的对白依据

摘要材料中的事件内含带 ID 的对白，模型引用这些对白 ID 原本会被校验误拒绝，因为允许列表只包含顶层事件。校验现在把本批材料中的对白 ID 映射回所属事件；其他批次或不存在的 ID 仍拒绝。真实第二章摘要已通过此修复继续执行。

### 同章后文资产提前进入早期场镜

场镜原先会因名字在当前原文出现，就把同章后文才抽取的资产加入候选。现在仅允许当前片段或此前已有依据的资产，不能提前使用后文形态。

### 上游 503 阻塞

第三章第 3 个片段连续收到 Xtasy `SERVICE_UNAVAILABLE`，供应商标记可重试。该片段原文仅 424 字，含记忆和结构约束的完整请求约 17,767 字符；此前约 23,000 字符的请求成功，不能认定为上下文过大。该片段低于最小拆分阈值，不继续切碎原文。同一模型最小请求有 HTTP 响应；同一失败输入将输出上限从 12000 降为 8192 后仍为 503。其他跨章理解请求继续成功。供应商未返回具体原因，未跳过章节，也未把前四章验收记为通过。

### 单章关联不能冒充跨章事实

真实回查中，模型曾为跨章关联只提供同章的两条引文，导致整批失败。现在把这种情况保留为“仅有本章依据，跨章关联待核对”，不写入已确认关联，也不阻断其他有充分依据的关联。引文不存在或完全不含本次所选 Note 的证据仍拒绝。

## 人物身份整理必要性

真实抽取第一章的两个片段就出现：

- 阳子分别使用“女高中生/班长”和“女高中生”作为身份范围。
- 同一导师使用“班导师”和“导师”两个称呼。
- 尚未揭晓姓名的男人使用“年轻男人”“怪怪的男人”等不同称呼。
- “毫发无伤”等基线状态也可能被模型写入外观衍生字段。

当前资产登记键包含模型自由填写的名字和身份范围，因此重复不只发生在跨章，也会发生在同章的跨片段阅读。仅有编号不能解决此问题。

应把“人物本体”“有依据的别名关联”“有适用时间的外观形态”分开。已有跨章身份理解与原生人工合并可复用；需要的是把疑似重复及其证据连接到合并操作，不应另建一套无依据的自动模糊合并。未揭晓身份必须保留当章称谓，关联不能把后文真实身份回灌到早期提示词。

本次仅评估必要性，不自动合并人物或改写原文阅读记录。

## 资产首次出现位置

人物、场景、道具和人物衍生形态保存 `first_note`（章节 ID、顺序、标题），按已生成且有效的 Notes 的原文顺序计算，而不是任务完成时间。后来补读更早章节时会更新首次位置；本体与衍生形态分别记录，人工合并时保留更早的来源。

资产卡片、详情及衍生行显示“首次出现：Note 001 · 章节标题”，点击跳回对应 Note。说明明确仅基于已生成 Notes，不推断未读章节。真实资产链接已在部署页面验证。

## UX 统一

- 泛读生成 Notes：首次读取所选章节，抽取梗概、资产、人物变化、事件和对白。
- 跨章精读回查：理解层默认开启，泛读完成后自动执行；独立按钮用于补查与重试。
- 明确回查只在可用章节范围内进行，移除“检索全书”的误导说明。
- 操作区按所选资料状态提示下一步：阅读、回查、SVT、待复核、仅留档或场镜生成。
- 提交 SVT 后直接切换到 SVT 页；展示爆点、爽点数量及不完整状态的操作说明。
- 故事设定统一为“从已生成 Notes 汇总故事设定”。
