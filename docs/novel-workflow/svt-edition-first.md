# 精简稿驱动的 SVT 与爆点提炼

范围为 Note → SVT/爆点。场镜生成、Note 抽取、精简稿生成和理解层不在本次变更范围内。

每批仍处理当前 Note 的最多八个事件，整章方向提供概况、事件索引及理解约束。批内连续叙述来自共享精简段落，每段只发送一次；事件保留完整 ID、人物、因果动作结果和信息性质，通过 passage_ids 引用段落。对白独立发送，保留完整原句、说话人、价值、来源事件和性质，不截断。

所有事件必须进入唯一主归属，包括过渡、没有对白和被精简稿省略的内容。保存的 Note、原文依据和对白对象不变。爆点继续采用场面＋原文台词＋来源 Note，并校验台词与事件一致。精简稿不是新的事实证据，不允许从转述补造台词。

精简段落缺失、空白省略、覆盖有缺口、标为不确定，或事件是推测/待定时，系统补入该事件的原文依据。其他因果或身份疑义可由模型通过 source_requests 请求本批事件原文；请求结果不直接发布，补入原文后再次提炼并执行完整校验。请求不能跨出当前批次。补读后仍无依据则保留未知，不强造爆点。常规每批一次生成，有补读时增加一次；每次沿用现有结构校验重试和项目调用上限，没有新增用户配额参数。

规则独立存于 `rules/svt_material.md`，项目可用同名规则替换，并可在规则页查看。SVT 的有效规则指纹包含该规则，因此缓存、前端有效性、后续场镜读取和人工主归属调整使用一致的版本判断。完整场景材料保持原有管线。

`svts.json` 和批次缓存记录 `material_stats`：初始提示词字符数（不含输出 schema、回查与校验重试追加内容）、共享段落数、事件和对白数、回查事件及原文片段数。字符数不是 token 数，也不是费用。历史 SVT 会按已有版本规则标记失效，原文和历史结果仍可查看。

验证使用同一第一章的 Note、精简稿和理解结论，不重新拆书。对比关注全部事件覆盖、关键剧情因果、原句与爆点场面关联、未知身份与后文信息边界，不要求爆点数量或标题逐字相同。输入压缩不能保证调用次数减少，也不能仅凭一次样本宣称所有长篇准确性不变。

单 Note 主 SVT 的概况直接复用已验证的整章概况，记录 `summary_mode=chapter_overview`。由于该 Note 的全部事件都属于唯一主 SVT，无需再次概括同一章，可避免二次归纳漏开端，并减少一次正常模型调用。跨多 Note 的 SVT 仍走有界累计汇总，标记 `summary_mode=cumulative`。标题和主线理由仍来自 SVT 提炼。
