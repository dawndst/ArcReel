# 片段内容承载、外观与开场状态

场镜素材库每个原文片段提供独立的检查区。阅读设置中的「内容承载、外观与开场状态检查」默认开启；关闭只隐藏入口、阻止新检查，不删除既有决定。

已有 Note 的事件按前提、阻力、行动／决定、结果建立承载清单。AI 审阅的是镜头实际音画，而非仅凭 event_id 关联就宣布完整；已存在的关键对白覆盖检查继续使用逐字匹配。工作人员可以指定承载 SH、明确省略并写理由，或撤销决定。AI 建议与人工决定分别存储，内容变化后旧决定标为待复核。列表是已有抽取记录的核查，不声称能证明 Note 本身完全无遗漏。

外观检查输入当前镜头使用的资产文字、当前状态、原文及截至该镜头的已读观察。区分身份、环境、年龄、形态、伤势和设计推断。结果有一致、冲突、依据不足三类，提供当前设计、原文与建议。人工可修改建议后采用为当前 SH 的外观约束，或记录无需修改；不自动覆盖角色母版。未读取参考图，不能把文字检查当成参考图已通过；工作人员从人物资产入口检查图片和选择正确变体。

每场开场状态有在场人物、位置朝向、道具持有、稍后入场四个文字字段。可直接手填，也可编辑 AI 建议后确认。不增加俯视图编辑器。只有选择原场第一镜时，确认后的开场状态才进入组集脚本；从中途选镜不会误用最初站位。外观约束随对应 SH 进入组集和制作信息。

检查只处理一个保存的原文片段（通常约6000字符），不重读全书、不自动重跑 Note/SVT，不生成视频。不设置语速预算或时长硬门槛，也不增加新的组集阻断。正常一次模型调用，输出校验失败最多三次；未变化的输入复用缓存，遵守项目现有调用上限。任务进度沿用现有工作流任务区。

原文回看与产物有效性分离。规则、SVT或理解更新不能阻止查看历史原文；生产是否有效仍沿用原检查。新场镜保存带摘要校验的原文快照，旧场镜没有快照时，只能对源文件完全相同且引句坐标一致的原文回看，不能把旧坐标套到另一本书。

数据位于 `novel_workflow/scene_library.json`：批次 `source_snapshot`、`craft_review`、`craft_decisions`；场 `opening_state`；镜头 `appearance_notes`。所有人工更新检查版本并写 history。模型规则位于独立的 `rules/craft_review.md`，可由项目规则替换，并显示在规则页面。生成缓存位于 `craft_cache/`。
