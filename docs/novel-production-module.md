# 小说理解与改编审查模块

## 开关与边界

剧情演绎项目的「项目设置 → 基础 → 小说理解与改编审查」控制 `novel_understanding_enabled`，缺省开启。关闭后不调用新增阅读、审查模型，不应用新增取舍上下文，使用 ArcReel 原有流程；已经采纳的大纲和合并不会自动撤销，缓存也不会被删除。

模块服务于登记为整本源文的小说。广告、旁白解说、纯成品剧本、自带原文但未建立整本位置映射的集沿用原流程，不宣称已经完成全书防剧透检查。混合源文仍以小说口径理解，分集继续尊重原生源文件类型边界。

## 生产路径

1. 生成故事设定或规划分集时，自动建立全文资料。也可以在分集页点击「建立资料 / 审查大纲」，任务进入原生文本队列并占用分集规划槽，避免与分集同时改写。
2. 以 20,000 字符为主阅读块，前置最多 1,000 字符重叠。事实必须附带本块中唯一出现的逐字引文，偏移由程序计算。每块独立落盘，失败重试复用完成块。新增模型调用使用 JSON 输出指令和本地 Pydantic 强校验，避免网关对复杂原生 Schema 返回不透明 503；结构错误最多重试三次，原始响应先落盘。
3. 每组最多八份摘要做树形归纳；完整原子事实独立保存，归纳不会覆盖事实。阅读覆盖率表示源文已处理范围，不等于事实提取召回率。
4. 分集保留 ArcReel 的滑动窗口与锚点校验。创作上下文仅提供当前边界前已出现的原文证据；全书摘要不注入早期分集。一个窗口生成多集时分别按每集结尾审查标题、节点和钩子，失败进入原有重试。
5. 分集后生成改编建议：必拍、压缩、省略、保留伏笔、保持/改写/与下一集合并。结合相关事实判断安静场景的因果与情绪作用，不以打斗多少决定取舍。
6. 用户查看建议大纲和原文证据，预览影响后采纳。合并调用原生 `merge_with_next_episode`，在原事务内校验建议基线并写入新大纲。原有产物按 ArcReel 的过期、退下及确认规则处理。
7. 剧情分镜与参考生视频两条脚本规划路径接收采纳后的取舍；模型生成结果经过证据审查。视觉提示词编写前检查当前内容，编写结果再次检查，最多三次安全反馈重试。

## 信息边界

- 作者核对资料：可检索全书事实、身份、年龄、形态、伤情、角色已知及叙事功能。
- 当前集创作资料：只传已验证且在读者揭示边界内的原文引文。摘要及模型归纳的人名/身份不直接传入，以避免同一个阅读块后半段污染前半段。
- 全局概述和累积资产描述不直接进入受保护的脚本/视觉编写上下文；保留当前文本提及的已登记资产名，具体状态依原文证据重建。
- 后台检查可以看到相关未来证据；反馈给创作模型只指出应改写的已生成文本，不回传隐藏真相。
- 自动审查存在模型误判和遗漏，不承诺零剧透。语义检索目前按主体/关联实体匹配；创作证据预算约 16,000 字符，审查最多选取 48 条已揭示和 48 条未来相关事实，按 32 条事实分组，改编建议选取最多 80 条相关事实。复杂隐喻、别名未归并、跨主体因果可能漏检。
- 已生成图片与视频的视觉内容没有在此模块中做多模态审核；手工资产描述、媒体直传与已存在成片不会因开启开关自动重做。图片资产人工确认仍有价值。

## 存储与规则替换

```text
<project>/novel_understanding/
  rules/{reading,synthesis,review,editorial}.md
  status.json
  runs/<source+rules+version digest>/
    rules.json
    status.json
    chunks/000000.json
    synthesis/<input digest>.json
    book.json
    responses/<stage>-<unique id>.json
    checks/<content digest>.json
  editorial/<proposal digest>.json
```

四种规则分别负责阅读、归纳、一致性与防剧透检查、改编取舍。首次使用复制到项目内，每个项目独立替换，不共享同一份可变规则。修改源文或规则会生成新缓存身份，保留旧资料用于排查。规则文件目前由文件层维护，没有新增规则编辑器。

建议指纹绑定当前集、下一源文集、原文/规则版本与目标时长。新增无关后续集不会让所有旧建议失效。采纳后记录取舍及大纲摘要；原文范围、大纲或全文版本变化后不再注入旧取舍。

## API

- `GET /api/v1/projects/{name}/novel-understanding`：启用状态、阅读阶段、覆盖率与当前有效建议。
- `POST /api/v1/projects/{name}/novel-understanding/review`：入队建立资料并审查大纲。
- `POST /api/v1/projects/{name}/novel-understanding/adopt`：`report_id`、`dry_run`、`confirm_episodes`、`confirm_merged_units`；先返回影响预览，再确认采纳。
- 项目创建/PATCH 支持 `novel_understanding_enabled`。

检查与进度数据存储在模块目录，不改变 ArcReel 原始 episode/source/script 数据格式的含义。阅读锁与项目提交锁分离，长时间模型调用不占用项目写锁；源文或开关在运行期间变化时停止沿用旧资料。

## 验证范围

定向测试覆盖默认开启、关闭不调用、阅读续跑、证据定位、未来引文隔离、每集独立边界、付费响应保存、安全反馈重试、规则失效、旧建议拒绝及原生合并。额外检查原生分集关闭模块后的兼容行为、前端开关与采纳确认。按照项目使用者要求不运行非必要全量套件。
