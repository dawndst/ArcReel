# 小说改编工作台：ArcReel 分工与实施顺序

## 产品决定

ArcReel 是生产工作台与唯一用户界面。沿用其项目、分集、脚本确认、资产、分镜、视频、任务及剪辑导出流程，不复刻旧工作台七个页面。小说理解与改编约束作为创作依据接入这些流程。

新项目由用户重新导入小说。不迁移旧项目、章节、草稿、资产、审核记录或生成任务；不因启动新工作台而删除旧站数据。可复用的是阅读算法、提示词经验和约束模型，而非旧产物。

## 实施状态

- 已建立独立 fork，保留 upstream remote，沿用上游许可证与署名。
- 已部署原生 ArcReel 独立实例；构建、HTTPS 登录、项目创建、合成源文导入与回收站操作已验证，未调用生成模型。
- 已完成[小说理解与约束层源码对比](novel-understanding-comparison.md)，下一步先做原生与 SKILL 增强的对照评估，再裁剪集成范围。
- 下述小说理解集成、生产约束和专项交互仍待实现，不将规划或 SKILL 文案视为后端能力已经完成。

## 保留的能力边界

| 能力 | 归属 | 接入原则 |
| --- | --- | --- |
| 源文导入、文件顺序、分集原文范围 | ArcReel | 使用其源文登记与变更机制，不另建一份可编辑原文 |
| 分批精读、实体归一、事实和证据 | 小说理解层 | 从已登记原文读取，保存源文版本、位置和引用 |
| 全书背景、时代地域、人物年龄／形态／状态 | 小说理解层 | 同一人物身份与不同外观变体分开；剧情时间与信息揭示位置分开 |
| 改编要求与有意偏离原著的决定 | 约束层 | 不修改原文事实；每次决定有独立版本、作用范围和理由 |
| 分集、脚本、资产和分镜生成 | ArcReel | 生成前按当前集、人物和场景检索依据，并冻结依赖版本 |
| 人物外观变体 | ArcReel 资产与衍生资产 | 使用原生资产引用；补充身份、阶段、形态、状态映射 |
| 图片确认、视频生成、剪辑导出 | ArcReel | 确认绑定到具体图片及设定版本；换图或换设定需重新确认 |

## 第一阶段：先建立原生生产工作台

部署独立实例和空数据根，不覆盖旧站。验证登录、创建与删除空项目、源文导入、任务状态及原生工作流入口。供应商凭证独立配置，真实模型调用另做验证，不能用首页可访问代替模型可用。

偏好为横屏 16:9、最低受支持画质、模型原生音频。具体模型的分辨率与音频能力仍由 ArcReel 的有效能力解析结果决定；不硬编码所有模型共用的请求参数。

## 第二阶段之前：比较原生能力与自研方案

部署完成后，先研究 ArcReel 已有的小说理解、上下文装配、脚本检查、资产衍生与依赖失效机制。逐项比较自研方案的收益、成本和真实缺口，并明确哪些可由 SKILL 改善、哪些需要服务端保障。完成比较后再决定以下集成范围，不预设整套自研系统都要移植。

## 第二阶段：小说理解落盘（待比较后裁剪）

先确定持久化契约，再移植阅读逻辑，不照搬旧 UI 或数据库。核心对象包括：

- 源文版本与范围：文件身份、内容指纹、字符区间、章节映射。
- 阅读运行与调用日志：冻结的 SKILL 版本、输入指纹、原始响应、解析状态、检查点。
- 实体与事实：稳定身份、别名、事实类型、断言强度、剧情有效范围、揭示位置、原文证据。
- 事实关系：补充、状态变化、冲突；冲突保留双方证据，不由摘要静默覆盖。
- 分层摘要：摘要依赖事实 ID，原始事实不被摘要替换。
- 生产上下文快照：任务目标、选中依据、预算、遗漏或阻断原因、依赖签名。

先按原文位置切块，再提取和归一，逐批提交事实与检查点。长上下文通过检索和分层摘要处理；强制约束超出预算时明确阻断，不截掉后假装已读取。读取完成、事实抽取完成和审核通过是不同状态。

精读、实体归一、事实合并、摘要、全书归纳、审核分别绑定可替换的 SKILL。运行中使用冻结版本；更换 SKILL 不改写已有运行。

## 第三阶段：接入生产与服务端检查

先列出 ArcReel 各入口的上下文装配点，包括 Web 操作、内嵌 Agent、外部 MCP 与任务重试。它们调用同一约束服务，不能只在聊天提示词中要求遵守。

1. 分集规划消费改编要求、世界背景及揭示边界。
2. 脚本规划消费当前集事实、人物状态和允许改编的决定。
3. 资产生成消费外观变体及其证据；未知年龄或形态不凭名称自动确定。
4. 提示词编写和分镜生成引用明确资产变体，不只引用人物名字。
5. 视频提交检查所用图片是否已按当前设定确认，冻结请求依据；已提交的付费任务仍按旧快照取回结果，不自动重发。
6. 上游变化只使依赖该变化的下游内容过期，保留旧版本供比较。

## 第四阶段：少量原生交互扩展

在 ArcReel 现有项目和制作界面增加「原文依据」「改编约束」「待解决冲突」，不再增加平行流程。人物资产展示身份及外观变体，引用选择器显示年龄、形态和状态。原文引用可定位；差异可查看；采纳后保存新版本。

用户确认图片和少量真实冲突，不要求用户重新通读全书。系统对未读、缺证据和理解不确定的范围如实提示。

## 验收

用合成测试文本覆盖跨年龄、变身、伤势恢复、地域背景、同名实体与晚揭示信息，不把某部小说特例写死。验证中途失败续跑、源文变化、SKILL 替换、重复任务、相关依赖失效与无关内容不失效。

重新导入的真实小说需完成一次从理解、分集到已确认图片的人工验收，再验证视频请求。单元测试通过不代表全文理解准确，也不代表供应商模型请求成功。
