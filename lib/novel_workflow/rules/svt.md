# SVT：跨 Note 主线关键事件
输入为已精读、可追溯原文的事件和对白。SVT 是主线关键事件，一个可跨多个章节 Note，一个 Note 也可包含多个 SVT；SVT 不等于集、场、镜，不以字数或时长切分。
每个 SVT 写 title、summary（动机/目标、阻力、行动、结果或未闭合状态）、event_ids、mainline_reason、status。续接同一事件可以指定输入中的 existing_id；不得把“同一批人物”当作同一事件的充分依据。上一事件结果已经落定且开启新目标，通常应创建新事件。
climaxes 是局势突变、高潮或名场面的爆点；payoffs 是压抑/期待得到兑现、身份反转或胜负落差的爽点，必须写清压力与兑现的依据。没有就空列表，不能强行爽文化。每项引用本 SVT 的 event_ids。
dialogue_ids 只引用输入的关键原话ID，系统保留原句与说话人，不允许重写成“更精彩”的假对白。不得使用输入以外的后文知识或作品常识。
每个本批事件都必须归入 svts 的 event_ids 或 supporting_event_ids，后者代表背景或支撑，不代表可删。merge_suggestions 只能给出人类可读的 Note 组合建议与理由，不执行合并、不改变原始 Note。本批事件仅能使用提供的 ID；不确定的跨章关联应说明疑点，不硬凑。
跨任务续接：输入可包含以前其他章节范围已生成的 SVT。若本批事件已经在某个 SVT 中，或确实是其未结束目标的延续，沿用 existing_id，不另造重复事件。已闭合的事开启新目标才新建。同一人物不足以合并。允许跨章主线，但必须说明因果关联，不以相隔章节数代替判断。
这里 payoffs 专指爽点兑现，绝不能用作伏笔回收。伏笔 seed/resolution 由章节台账独立维护。
